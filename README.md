# لُب | Lub Studio

غرفة عمل عربية لصناعة المحتوى من الأخبار والبيانات: أفكار وقصص، مصادر، إنتاج، مراجعات، اعتماد، خطة نشر، مهام وفريق، ومؤشرات تشغيل داخلية.

## الحالة الحالية

نسخة أولى تعمل باستخدام React وTypeScript وVinext، مع Cloudflare D1 وDrizzle لحفظ البيانات. تدعم الواجهة العربية واتجاه RTL. يحتوي المستودع على المصدر وترحيلات قاعدة البيانات والاختبارات؛ لا يحتوي على بيانات الإنتاج أو الأسرار.

يعمل الآن دخول الفريق بحسابات مستقلة: تهيئة المالك، دعوات لمرة واحدة، سبعة أدوار، تعطيل وتفعيل، روابط استعادة الوصول، وصلاحيات تُفرض في الخادم على كل عملية، مع سجل نشاط يذكر منفذ كل تعديل واعتماد ونشر.

وتعمل دورة التحرير: مصادر متعددة بجهاتها وتواريخها، ادعاءات وأرقام مرتبطة بمصادرها، مخرجات X بعداد أحرف، قائمة تحقق للمراجعة، تعليقات وقرارات، إصدارات محفوظة لكل تغيير في المحتوى، واعتماد مرتبط بإصدار محدد يُلغى هو والجدولة عند تعديل المادة.

النشر إلى X وإحصاءات الجمهور غير مربوطين بعد. مواعيد النشر تخطيطية، وإثبات النشر اليدوي يستخدم رابط المنشور. المواد المرئية تُربط بروابط، والرفع المباشر غير منفذ. الدعوات لا تُرسل بالبريد؛ يُنسخ رابطها ويُرسل يدويًا. خطة المراحل التالية في `PLAN.md`.

## التشغيل المحلي

المتطلبات: Git، وNode.js بالإصدار 22.13 أو أحدث، وpnpm بالإصدار المحدد في `package.json`.

```sh
git clone https://github.com/sabq4org/lub-studio.git
cd lub-studio
pnpm install --frozen-lockfile
pnpm run build
```

أنشئ ملف الأسرار المحلي من النموذج، وضع قيمة عشوائية طويلة في `LUB_SETUP_TOKEN`:

```sh
cp .dev.vars.example .dev.vars
```

بعد أول بناء، طبّق الترحيلات على قاعدة البيانات المحلية بالترتيب، **كل ترحيل مرة واحدة فقط**:

```sh
for f in drizzle/0000_silky_wraith.sql drizzle/0001_team_accounts.sql drizzle/0002_editorial_cycle.sql; do
  node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file "$f"
done
pnpm run dev
```

إذا كانت قاعدتك المحلية مهيأة سابقًا، طبّق الترحيلات التي لم تُطبق بعد فقط. افتح العنوان الذي يطبعه الخادم، وعادةً `http://localhost:5173`. أول زيارة تعرض شاشة تهيئة المالك وتطلب قيمة `LUB_SETUP_TOKEN`. قاعدة البيانات المحلية منفصلة عن قاعدة النسخة المنشورة.

## الحسابات والصلاحيات

| الدور | ما يستطيعه |
| --- | --- |
| المالك | كل شيء، وإدارة الحسابات والدعوات والأدوار |
| مدير التحرير | إدارة القصص والإسناد والاعتماد والمهام وأعضاء الإسناد، وقراءة سجل النشاط الكامل |
| باحث أو محرر | إنشاء أفكار تُسند إليه، وتعديل محتوى القصص المسندة إليه ونقلها حتى المراجعة |
| مصمم أو منتج | تعديل الأصول والحقوق في القصص المسندة إليه وإرسالها للمراجعة |
| مراجع | ضبط قائمة تحقق المراجعة، وإعادة المواد من المراجعة مع سبب (القصص المسندة إليه أو غير المسندة لمراجع) |
| مسؤول النشر | ضبط موعد النشر للمواد المعتمدة، وجدولتها وإلغاء جدولتها، وتوثيق نشرها |
| مشاهد | الاطلاع فقط |

- كل طلب إلى `/api/*` يتحقق من الجلسة، ثم من الدور، ثم من إسناد القصة وحقولها. إخفاء الأزرار في الواجهة للتوضيح فقط.
- الجلسة رمز عشوائي في ملف تعريف `HttpOnly` و`SameSite=Lax`، ويُحفظ في D1 مجزأً. كلمات المرور مجزأة بـ PBKDF2-SHA256. محاولات الدخول الفاشلة تُقفل البريد 15 دقيقة بعد 8 محاولات.
- تعطيل الحساب أو تغيير دوره ينهي جلساته فورًا. لا يمكن تعطيل آخر مالك نشط، ولا تغيير دورك بنفسك.
- استعادة الوصول: ينشئ المالك رابط استعادة لمرة واحدة صالحًا 24 ساعة. إذا فقد المالك الوحيد وصوله، يستخدم «استعادة وصول المالك» في شاشة الدخول مع `LUB_SETUP_TOKEN`.
- ربط دعوة بعضو إسناد قائم يجعل الحساب يرث القصص والمهام المسندة إليه.

### متغيرات الخادم

| المتغير | الغرض |
| --- | --- |
| `LUB_SETUP_TOKEN` | سر لإنشاء أول مالك واستعادة وصوله. بدونه لا تمكن التهيئة في الوضع `local`. |
| `LUB_AUTH_MODE` | `local` (الافتراضي) يتجاهل ترويسات الهوية تمامًا. `sites` يثق بترويسات `oai-authenticated-user-*` التي تحقنها Sites، ويُنشئ المالك الأول من تلك الهوية. لا تضبطه على أي استضافة أخرى. |

## التحقق

```sh
pnpm run typecheck
pnpm test
pnpm run build
```

الاختبارات تستخدم قاعدة D1 معزولة عبر Miniflare وتطبق كل الترحيلات. `scripts/check-lub.mjs` يتحقق من الحفظ، وانتقالات العمل، ومتطلبات المراجعة، وإلغاء الاعتماد بعد تعديل المادة، وتعارض نسخ التحرير، وحفظ أعضاء الإسناد والمهام. `scripts/check-access.mjs` يتحقق من رفض الطلبات دون جلسة أو بترويسات مزورة، وسر التهيئة، وتجزئة كلمات المرور، وقفل المحاولات، والدعوات (لمرة واحدة، الانتهاء، الإلغاء)، وصلاحيات كل دور على القصص والمهام، وقصر النشر على مسؤول النشر والمالك، وسجل النشاط، وإنهاء الجلسات عند التعطيل، وحماية آخر مالك، وروابط الاستعادة، ووضع Sites. `scripts/check-editorial.mjs` يتحقق من المصادر والادعاءات، وقاعدة المصدر السعودي الرسمي، وحد 280 حرفًا، وصلاحيات قائمة التحقق، وسبب الإرجاع، والإصدارات، وربط الاعتماد بإصدار، وإلغاء جدولة المادة المعدلة، والتعليقات والقرارات.

## الاستضافة والوصول

النسخة الأصلية منشورة على Sites. إعدادات البناء الحالية تشمل تكامل Sites وCloudflare D1. نقل الكود إلى GitHub لا ينقل قاعدة بيانات الإنتاج، ولا يغيّر الاستضافة أو صلاحيات الوصول. معرّف المشروع الموجود في `.openai/hosting.json` يحدد النسخة الأصلية، وليس مفتاح وصول.

التطبيق يفرض الآن مصادقته وصلاحياته بنفسه، فلا يعتمد على حماية Sites لمنع الوصول. عند النشر على Sites يمكن إبقاء خصوصية Sites طبقة إضافية.

**قبل نشر هذا الفرع على النسخة الحالية** يلزم تطبيق `drizzle/0001_team_accounts.sql` ثم `drizzle/0002_editorial_cycle.sql` على قاعدة الإنتاج (ترحيلات إضافية لا تعدّل الجداول الحالية)، ثم ضبط `LUB_SETUP_TOKEN` أو `LUB_AUTH_MODE=sites` في بيئة الخادم. بدون ذلك ستعرض النسخة شاشة التهيئة ولن يمكن الدخول. المواد المعتمدة سابقًا تحتاج إعادة اعتماد قبل جدولتها أو توثيق نشرها. هذه خطوات إنتاج لم تُنفذ وتحتاج موافقة صريحة.

تفاصيل بيئة التشغيل الموروثة في `docs/RUNTIME.md`، وحدود النسخة وخطة الإكمال في `IMPLEMENTATION.md`.
